# Every variable of the runtime that lives between calls, and what a snapshot
# does with it (runtime/snapshot.c, docs/SNAPSHOT.md). tools/tests/test_snapshot.py
# compiles runtime/ as a host build, lists every data and bss symbol of every
# object (a function's static as name.N, read here as name), and holds this
# file to that list both ways: a variable added without a line here fails the
# suite, and so does a line for one that is gone. A line `saved` also needs
# the name in its file's *_snap function.
#
#   file  name  how  # why
#
# how:
#   saved    in the file's section: restored as it was (or, where the comment
#            says, as the snapshot's frame makes it)
#   cpu      the CpuState and MEM1: snapshot.c's cpu and mem sections
#   config   read from the environment, or set up by main.c, at the start of
#            every run, so the same in a resumed one (a resume continues one
#            run: its switches are that run's)
#   report   a count, a timer or a log's state that the report or a log line
#            prints; nothing the guest sees
#   host     what a host or a window reads (frames, models, sound, rumble),
#            made again from what the guest does from the resume on
#   scratch  plumbing: locks, threads, handles, queues and buffers that are
#            empty or unused at the safe point (or remade on the next call)
#   refused  a mode a snapshot is refused in (mods, a recording, a GPU
#            backend, a pair replay, the self test): its state never needs one
